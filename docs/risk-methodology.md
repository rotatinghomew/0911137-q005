# 风险估计与备件口径

本文件说明风险分析（`/api/view` 返回的 `risk` 部分与设备页）采用的统计口径。所有计算只依赖 Python 标准库，结果随分析版本一起冻结保存。

## 时间尺度与暴露

- 时间尺度是**累计运行小时（operating age）**，不是业务日历。`intervals` 的半开区间 `[start_hour,end_hour)` 按并集去重，区间之间的停机间隙不计入暴露；区间上的 `load` 是业务负荷记录，本版模型不把负荷折算成额外时间。
- 一台设备在大修处被切成多个寿命片段（episode）。片段内使用局部年龄：大修后的片段从运行年龄 0 重新计龄；小修不切片段、不归零。

## 竞争结局与维修等级

- `failure`（故障）与 `retire`（报废）是竞争结局。报废片段在报废年龄离开风险集，报废之后不再计暴露、不会再发生故障。
- `inspection`（计划检修）只是事件，不是故障，不改变年龄，不进入风险集事件计数。
- 维修等级按现有资料的两档解释，不引入资料外的假设：
  - `overhaul`（大修）：解释为年龄重置，开启新寿命片段；
  - `minor`（小修）：不重置年龄，设备留在同一片段继续在险，故障按可复发事件计数。
- 重置解释是**建模约定而非被资料验证的事实**：现有资料中维修后没有任何故障，无法从数据识别大修是否真的恢复到新机状态。因此维修后片段单独成组，只给零事件上界，不与首段故障率混算。

## 故障率与置信区间

- 首段（未经大修重置）按站点估计恒定故障率 λ = 故障事件数 / 运行小时暴露，服从 Poisson 假设；区间用精确（卡方）Poisson 区间而不是正态近似，零事件站点因此得到有效的单侧上界（3/n 法则的精确形式 χ²(0.975,2)/(2n)）。
- 风险集表按运行年龄给出每一年龄点的在险片段数、故障数、报废数、Nelson–Aalen 累计风险与 Kaplan–Meier 生存函数。该表是描述性的首次事件视图；小修后继续在险的复发故障在 Poisson 率中计数，但不会在 KM 中重复离开/进入风险集。

## 跨站点信息借用

- 借用前先做等率检验：在“各站点故障率相同”的假设下，给定总故障数 K，故障按各站点暴露占比服从多项分布；故障最集中站点的单侧条件二项尾部概率即检验 p 值。
- 当前资料（cutoff 2400）：三站点暴露接近（29800 / 30300 / 29800 运行小时），但 16 次故障全部发生在站点1，站点2、站点3 零故障，p ≈ 2.1×10⁻⁸；批次在站点间均衡分布、平均负荷接近，批次与负荷不能解释差异。结论是**不支持把站点1 的故障率借给站点2、3**。
- 因此主口径是各站点自身证据：零故障站点的率 MLE 为零，只保留零事件 95% 上界。借用全网首段率的结果仍会计算，但仅以“敏感性对照”情景返回，页面明确标注其不被检验支持。

## 预测状态：不凭外推凑精确风险

设备级预测分两个层次返回，避免把假设当成观测：

| 状态 | 含义 |
| --- | --- |
| `estimated_within_observed_age` | 预测窗口落在已观测故障年龄范围内，给点估计与区间 |
| `beyond_observed_age` | 当前运行年龄已超过最大观测故障年龄（当前资料为 900 运行小时），严格口径不提供点估计；同时返回恒定率模型外推值，并显式给出无观测支持的外推小时数 |
| `insufficient_post_repair_evidence` | 大修后片段零故障，点估计不可识别，只给零事件 95% 上界概率 |
| `retired` | 已报废，不进入未来需求 |

`extrapolation` 字段使用恒定故障率（指数）模型：P = 1 − exp(−λh)，区间来自 λ 的精确 Poisson 区间。它是情景假设，不是观测结论；`strict_probability` 为 null 时页面不显示精确概率。

## 备件需求范围

对预测窗口（`horizon_hours`，单位为运行小时，默认 720）返回两层需求：

- **严格口径** `strict_expected_failures`：只累计观测年龄支持部分的期望故障数，超龄与维修后设备不贡献点估计；
- **模型口径** `model_expected_failures` 与 Poisson 95% 预测区间：恒定率模型下的期望故障数及预测分位数；
- **保守上界** `conservative_upper_need`：各设备率区间上界概率之和（含维修后零事件上界）对应的 Poisson 95% 分位，作为备货上限参考。

这些数字是未来运行小时窗口内的故障备件需求，不是确定订单，也不直接等于日历三个月；班组需按实际排班把运行小时换算成日历周期。

## 历史时点可复现

所有事件、维修与运行区间都按 `known_hour <= cutoff` 过滤。例如 cutoff=900 时故障（业务时标 1000、获知 1010）与维修（1100）均不可见，分析结果不包含任何未来信息；cutoff=1050 可见故障但不可见维修，片段不会被提前切开。
